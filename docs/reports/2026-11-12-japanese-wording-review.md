# 日本語の文言の点検

実施日: 2026-11-12

## はじめに

この文書は、AI Assistant for OBS Studio の日本語の文言の問題点を一覧にしたものです。目的は指摘の一覧の作成であり、対象のファイルは書き換えていません。直す案は案として示します。

対象は次の 3 つです。

- `data/locale/ja-JP.ini`: ドックと設定画面の文言、提案の項目名
- `README.md`
- `docs/logs/2026-11-12-conversation-review.md` の「AI アシスタント」の回答と提案の理由。これらはモデルが書いた文なので、直す案は `src/core/instructions.cpp` の指示文に書く内容として示します

観点は優先の順に次の 4 つです。表の「問題」の列では、この番号で観点を示します。

1. 用語の一致: 同じものを同じ名前で呼び、違うものを違う名前で呼ぶこと。基準は OBS Studio 本体の日本語の画面の用語です
2. 文章の規約: `documentation.md` と `working-principles.md` の規約
3. yomiyasu の lint の候補のうち、yomiyasu の SKILL.md の 1 章の観点で当たると判定したもの
4. 依頼者の指示: 「動かす」「動く」を使わず「動作」を使うこと

重大さは、OBS の画面で同じ項目を探すときの妨げの大きさと、文の意味の取り違えやすさで、高・中・低の 3 段階に分けました。

## 検証方法

OBS の公式の訳は、ビルド用に取得済みの OBS Studio 33.0.1 のソースにある次のファイルから引きました。キーと値は検索で確かめ、表にはキーと値をそのまま載せています。

- `.deps/obs-studio-33.0.1/frontend/data/locale/ja-JP.ini`: 本体の画面
- `.deps/obs-studio-33.0.1/plugins/obs-filters/data/locale/ja-JP.ini`: フィルタの種類の名前
- `.deps/obs-studio-33.0.1/plugins/win-capture/data/locale/ja-JP.ini`: 画面キャプチャとゲームキャプチャ
- `.deps/obs-studio-33.0.1/plugins/win-wasapi/data/locale/ja-JP.ini`: 音声の入力と出力のキャプチャ、アプリケーション音声キャプチャ

ブラウザソースの訳を持つ obs-browser の言語ファイルは `.deps` の下にありませんでした。そのため、ブラウザソースの種類の名前は確かめられていません。

文章の規約は、`C:/Users/scher/.claude/rules/documentation.md` と `C:/Users/scher/.claude/rules/working-principles.md` を読んで当てました。

yomiyasu の lint は `yomiyasu_lint.py 2.5.0` を `python3` で実行しました。ini は値だけを抜き出し、`\n` を改行に直した写しを検査しました。会話の記録は「AI アシスタント」の回答と提案の理由だけを抜き出した写しを検査しました。写しは作業用の一時フォルダーに置き、リポジトリには置いていません。実行したコマンドは次のとおりです。

```
python3 C:/Users/scher/.claude/skills/yomiyasu/scripts/yomiyasu_lint.py --doc-type manual <ini の写し>
python3 C:/Users/scher/.claude/skills/yomiyasu/scripts/yomiyasu_lint.py --doc-type manual D:/work/ai-assistant-for-obs/README.md
python3 C:/Users/scher/.claude/skills/yomiyasu/scripts/yomiyasu_lint.py --doc-type mail <AI の回答の写し>
```

候補の数は、ini の写しが 3 件、README が 8 件、AI の回答の写しが 5 件でした。各候補の採否は後述の「lint の候補の判定」に載せています。

あわせて、提案の項目名と値の組み立て方を `src/dock.cpp` と `src/obs-tools.cpp` で確かめました。会話の記録の元になった `.logs/2026111229-review/runs/` の入力も確かめました。

## 考察

重大さを高とした指摘は 2 つの種類に分かれると考えています。1 つは、承認の画面に OBS の内部のキーと値がそのまま出ることです。もう 1 つは、AI の回答が OBS の画面の項目名と違う語を使うことです。どちらも、利用者が OBS の画面で同じ項目を探せなくなります。承認の可否を利用者が判断する画面でこれが起きるため、文言の直しの中で最も優先度が高いと考えています。

上位 10 件は次の順だと考えています。

1. 提案の項目名と値に内部のキーと値が出る (`Proposal.SourceSetting` などと `value_text`)
2. 音声モニタリングの値が `off` と `monitor_and_output` のまま出る
3. AI の回答のキャプチャ方式。OBS ではキャプチャ方法
4. AI の回答のモニターが、ディスプレイ・音の出力機器・音声モニタリングの 3 つを指す
5. AI の回答のモニターをオフ。OBS の値はモニターオフ
6. AI の回答の映像設定が映像ビットレートを指し、OBS の映像タブと衝突する
7. AI の回答の 80 行目の副作用の文の意味が読めない
8. フィルターとフィルタ、クロップとクロップ/パッドのずれ
9. 送り先を OpenAI と AI の 2 つの名前で呼ぶこと
10. 配信中の音声の変更の注意が、指示文とドックの両方から別の言い方で出ること

AI の回答の用語をそろえる対策は、強度の順に次の 3 つがあると考えています。

| 案 | 効果 | 失敗する条件 | 副作用 |
| --- | --- | --- | --- |
| 道具の結果に OBS の画面の項目名と選択肢の名前を必ず入れ、指示文で「その名前で呼ぶ」と書く | モデルは結果の語を写すため、OBS の言語の設定に合った語になると推測します | OBS の画面の言語と会話の言語が違うとき。出力の設定のようにプロパティを持たない設定では、対応表を別に持つ必要がある | 送る量が増え、費用が少し増える |
| 指示文に日本語の用語の表を置く | 表にある語はそろうと推測します | 表にない項目。OBS の版が変わり訳が変わったとき | 指示文が長くなり、日本語以外の会話にも表が送られる |
| 何もしない | なし | 常に | 現状のずれが続く |

`src/obs-tools.cpp` 873〜875 行目では、リストのプロパティの `description` と選択肢の `label` をすでに道具の結果に入れています。一方、会話の記録の元の入力の `.logs/2026111229-review/runs/gpt-6.1-terra-low__01-black-screen.json` には `description` がありませんでした。そのため、実際の OBS でのモデルの言い方は確かめられていません。実機での確認が 1 つ目の案の前提になると考えています。

依頼者の指示の「動作」への置き換えでは、151 行目の「メーターが動く」が「メーターが動作する」になると不自然だと考えています。指摘の一覧では「メーターの反応」を案にしました。この置き換えの採否には、依頼者の判断が要ると考えています。

ブラウザソースの種類の名前は、obs-browser の言語ファイルが手元にないため確かめていません。`Help.Body` と README の「ブラウザソース」をそろえる前に、OBS の画面かリポジトリの obs-browser で確かめる必要があると考えています。

`docs/INDEX.md` は、依頼の範囲がこのレポートの作成だけだったため更新していません。
