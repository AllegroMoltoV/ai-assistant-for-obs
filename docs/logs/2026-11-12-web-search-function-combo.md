# Web 検索と独自の関数の併用の確認

実施日: 2026-11-12

## はじめに

Responses API で、Web 検索の道具と独自の関数を同じ `tools` 配列に入れて使えることを確かめました。道具の定義と要求の組み立ての層 (子課題 .2) の方式は、この結果に依存します。

## 検証方法

- モデルは `gpt-6.1-terra`、推論の強さは `low`、`store: false` です。`include` に `web_search_call.action.sources` と `reasoning.encrypted_content` を指定しました。
- `tools` には `{"type": "web_search"}` と、引数の無い関数 `get_obs_status` を入れました。指示文では、原因を推測する前に `get_obs_status` を呼び、状態に関係する既知の問題を Web で調べるよう求めました。
- 1 回目は利用者の発話「OBS で配信していると映像がカクつきます。原因を調べてください。」だけを送りました。
- 2 回目は、1 回目の入力と出力のアイテムに、`function_call_output` として模した状態を足して送りました。模した状態は、x264 の veryfast、1080p・60 fps、エンコードの遅れによるスキップ 18.4%、CPU の使用率 93%、GPU は RTX 3060 です。
- 送信は `.tmp/2026111201-send-responses.ps1` で行いました。API キーは `.tmp/.env` から読み、表示も保存もしていません。生の応答は `.logs/2026111201-round1-response.json` と `.logs/2026111202-round2-response.json` にあります。

## 検証結果

| 項目 | 1 回目 | 2 回目 |
| --- | --- | --- |
| HTTP の状態 | 200 | 200 |
| 応答までの時間 | 2,731 ms | 11,878 ms |
| 出力のアイテム | `function_call` (`get_obs_status`、引数 `{}`) | `reasoning`、`web_search_call` (検索 1 回、参照した URL 15 件) 、`message` |
| `usage.input_tokens` | 4,623 (うちキャッシュの書き込み 4,620) | 13,088 (うちキャッシュの読み出し 4,620) |
| `usage.output_tokens` | 15 | 531 (うち推論 72) |
| `tool_usage.web_search` | 記録なし | `num_requests: 1` |

2 回目の `message` には `url_citation` の注釈が 3 件付いていました。出典は OBS の公式のヘルプ 2 件とフォーラム 1 件です。URL の末尾には `?utm_source=openai` が付いていました。

回答の要旨は次のとおりです。

> 確認したところ、**最も可能性が高い原因はエンコード処理の負荷**です。
> (中略)
> 1. **配信をいったん停止**し、OBSの「設定」→「出力」で、配信エンコーダーを **NVIDIA NVENC H.264** に変更します。

回答は Markdown の太字・見出し・番号つきの箇条書きを含んでいました。

応答の `usage` には、Web 検索で取り込んだ内容のトークン数を分けて示す欄はありませんでした。`tool_usage.web_search` にあるのは検索の回数だけです。

## 考察

- Web 検索と独自の関数は同じ `tools` 配列で併用できると考えています。モデルは指示どおり先に関数を呼び、その結果を受けて検索しました。
- 1 回目の入力が 4,623 トークンあったのは、Web 検索の道具を有効にしたことによる固定の上乗せだと推測します。関数 1 つと短い指示文だけでは、この量にならないためです。キャッシュに載るため、2 回目以降の単価への影響は小さいと考えています。
- Web 検索の取り込み量は `usage` から直接は取れません。モデルの試験 (.3) では、Web 検索を無効にした同じ場面との `input_tokens` の差で見積もる必要があると考えています。
- 回答が Markdown で返るため、ドックの画面 (.5) では Markdown の表示に対応するか、指示文で書式を制限する必要があると考えています。
- 12.8 万トークンの制限が会話の全体にかかるか、検索の内容だけにかかるかは、この結果からは判断できませんでした。
